# Merge test data

Each folder is one scenario of the **first-connection merge** (`SYNC-FORMAT.md`, "Turning sync on"):

* `local.json`    – this device's bookmarks before turning sync on: `{ "Work": [...], "Private": [...] }`
* `remote.json`   – what the sync file holds, same shape
* `expected.json` – the result of merging `remote` into `local`, same shape

`expected.json` was **generated by running the Windows implementation** (`BrowserStore.MergeBookmarks`) on the two inputs, so it is the reference. An implementation
passes a scenario when its merged lists equal `expected.json` structurally (titles, URLs, children, order).

What the two scenarios show, by example:

* `basic`: a link whose URL is already local is dropped even when its title differs; a remote folder `Dev` that exists locally is **not** merged into the local `Dev` - a second
  folder `Dev` is added holding only the missing link `D`; new folders arrive with their missing links; Private is merged the same way.
* `nested-and-empty`: a nested folder whose only link is known disappears (and so does the folder that held only it); an empty remote folder and a folder whose links are all known
  are dropped; a URL that appears twice in the file is added twice (the known URLs are taken from the local data only).
